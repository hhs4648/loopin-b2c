2026-10-20 선생님: 보기 고를 때 「문장 보기」·▸ 해석·단어 뜻을 누르다 답을 잘못 누르는 일이 잦다 → 보기를 누르면 **고르기만**(분홍 테두리), 아래 **[제출]**을 눌러야 답. 모든 시험 보기 화면(바로 풀기·분석 뒤·문장 넣기 숫자형).

분석 뒤 문제(analysis_first): 틀린 보기를 지우고 다시 고르게 하며 하나씩 설명하던 흐름은 수업을 너무 길게 해서 없앴다. **한 번 제출하면** 「정답이에요!」 또는 「아쉽게도 틀렸어요. 정답은 ②예요.」 + 다섯 보기 아래에 짧은 해설을 다 펼친다(정답은 answer_explain, 오답은 option_feedback, 내가 고른 건 「내 답 · 오답」). 「다음으로」 → answer_note(있으면) → 다시 볼 주기.

**Why:** 어차피 분석을 다 했으니 보기 해설은 요약이면 된다. 수업 길이를 줄인다.
**How to apply:** option_feedback은 보기 아래 한두 줄 요약으로 쓴다. 많이 고른 오답(option_review)은 강제하지 않고 그 보기를 골랐을 때만 [같이 자세히 볼래요] 버튼 — 설명 한 화면만 보고 보기 해설 화면으로 돌아온다(다시 고르지 않음). 「어디서 헷갈렸어요?」 선택지 질문은 학생이 피곤해서 뺐다(2026-10-20 선생님) — 이런 되묻기 질문은 넣지 않는다. [[reference-lesson-2026-q21]]

**보기 목록 잘림 (2026-10-20):** 낮은 폰에서 보기·[제출]이 화면 밖으로 밀려 못 고르던 문제 — 아래 칸(.study-dock)이 줄어들 수 있게(flex 0 1 auto, min-height 0), 줄어드는 건 보기 목록(스크롤), [제출]은 목록 밖에 둬서 늘 보인다. 400×720·360×600에서 확인.

**바로 풀기·코스 풀기 (2026-10-21):** 지문 미리보기에서 보기를 누르면 고르기만(분홍), 아래 [정답 확인하기]로 채점(`PassageFull`). 「실제 시험처럼 풀어 봐요. 위 보기에서 답을 골라요 / 풀지 않고 분석 먼저…」 안내 말은 뺐다 — 풀 때는 말하지 않는다.
