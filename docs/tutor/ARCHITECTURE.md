# 다정쌤 아키텍처

Loopin B2C의 AI 튜터는 챗봇이 아니다. **고정된 교습 절차를 실행하는 상태머신**이고, LLM은 그 절차가 빈칸을 줄 때만 말한다.

원칙 한 줄:

> 틀은 고정(단계 · 고정 대사 · 처치). 모델은 틀 안에서만 자유(예상 밖 응답, 연결어, 부분 정답 판정).

haksup 앱의 튜터/채점/화면을 가져오지 않는다. 화면 셸은 상냥쌤 HTML 프로토타입, 캐릭터 이름은 **다정쌤**.

---

## 1. 레이어

```
┌─────────────────────────────────────────────┐
│  UI 셸                                      │
│  교실 대화 / 문장 학습 / 칩·버튼·입력바      │
└────────────────────┬────────────────────────┘
                     │ TutorView
                     │ { message, buttons, effect, sentence, properNouns }
┌────────────────────▼────────────────────────┐
│  세션 엔진 (코드, 진실의 원천)               │
│  stage, unitIndex, hintRung, missCount,     │
│  pendingBranch, 한 턴 파이프라인             │
└───────┬──────────────────────────┬──────────┘
        │ 액션 결정                 │ 레슨 조회
        ▼                          ▼
┌───────────────┐        ┌────────────────────┐
│ LLM 어댑터    │        │ 콘텐츠             │
│ (나중)        │        │ frame.json         │
│ D만 생성      │        │ lessons/*.json     │
│ 말은 틀 안    │        │ 고유명사, P1–P3    │
└───────────────┘        └────────────────────┘
```

| 레이어 | 바꾸는 이유 | 안 바꾸는 이유 |
|--------|-------------|----------------|
| **프레임** `frame.json` + 엔진 | 교습 철학이 바뀔 때 | 문장이 바뀔 때 건드리지 않음 |
| **레슨** `lessons/*.json` | 새 지문, 새 예상 오류 | 말투·힌트 단수·선공개 금지를 여기 넣지 않음 |
| **엔진** `src/tutor/engine.ts` | 카운트·분기·화면 전환 | 개별 문장 해석을 하드코딩하지 않음 |
| **LLM** | 예상 밖(D), 부분 정답(B) 판정, 말 다듬기 | 힌트 점프, 다음 문장 혼자 진행, 정답 선공개 |
| **UI** | 말풍선 위치, 칩, 버튼 렌더 | 교습 순서를 UI가 발명하지 않음 |

지금 데모는 LLM 없이 엔진이 P1/P2/P3를 매칭하고, 그 외는 E(힌트 사다리)로 접는다. 프로덕션에서는 E는 그대로 두고 D만 LLM으로 연다.

## 2. 한 수업의 생명주기

```
intro ──► unit 1 ──► unit 2 ──► … ──► unit N ──► done + [기록]
              │
              ├── A 정답 ──────────────────────► 다음 unit
              ├── C 예상오류(P2/P3) ──► 2지선다 ──► 재시도
              ├── B 부분정답 ──► 맞은 점 인정 후 틀린 점만
              ├── E 모름 ──► 힌트 1 → 2 → 3 (한 턴에 한 단)
              └── D 예상밖 ──► (지금) E와 동일 / (나중) LLM
```

**unit** = 한 번에 해석할 덩어리. 기본은 **문장 하나**. 문장이 실제로 길 때만 청크로 자른다. 짧으면 끊지 않는다.

고유명사(Lewis Ltd. 등)는 unit이 시작되기 **전**에 제시한다. 해석 과제가 아니다. 화면에 칩으로 남기고, 같은 설명을 매 문장 반복하지 않는다.

---

## 3. 세션 상태 (코드만 기억)

LLM 대화 히스토리에 맡기지 않는다. 힌트 단수와 좌절 카운트가 깨진다.

```ts
type SessionState = {
  lessonId: string;
  stage: "intro" | "unit" | "pending_choice" | "wrap_up" | "done";
  unitIndex: number;
  hintRung: 0 | 1 | 2 | 3;
  missCountInUnit: number;     // 오답 + 모르겠어요. unit이 바뀌면 0
  pendingBranch: string | null; // 2지선다 대기 중이면 그 오류 id
  reachedHint3: boolean;        // 3단(정답 공개)을 본 문장이 있었나 → 결과 「취약」
  properNounsTold: string[];    // 이미 제시한 고유명사
  hadAnyError: boolean;
  skipFinalRetake: boolean;     // 좌절 방지 발동
  lastTutorUtterance: string;
  errorIds: string[];
  result: "이해" | "오류후이해" | "설명제공" | "취약" | null;
};
```

**이 표가 단일 소스다.** 실물은 `src/tutor/engine.ts`의 `EngineState`.
지금 데모가 아직 안 가진 것: `pending_choice`·`wrap_up` 단계(2지선다는 별도 필드로
들고 있고, 마무리 통합 재시도는 없다), `properNounsTold`(칩은 문장에서 매번 뽑는다).

규칙:

- miss는 **현재 unit 안에서만** 합산한다.
- 힌트를 줘도 miss에 포함한다.
- miss가 3이고 네 번째가 오면 힌트를 더 오르지 않고 **설명제공**으로 전환한다.
- unit이 넘어가면 `hintRung = 0`, `missCountInUnit = 0`, `pendingBranch = null`.

## 4. 한 턴 파이프라인 (고정 순서)

학생 입력(버튼 또는 자유 텍스트)이 오면 엔진은 아래만 실행한다. 순서를 바꾸지 않는다.

1. **빈 입력** → 무시.
2. **역질문인가?** (`~가 뭐예요?`, 고유명사 질문)  
   오답으로 세지 않음. 짧게 답하고 수업 복귀. 고유명사면 “그대로 써도 된다” + 원하면 2줄 설명.
3. **pending 2지선다인가?**  
   선택지 매칭 → 고정 대사. 정답을 새로 강의하지 않음.  
   선택지 밖이어도 **그게 정답이면 정답으로 받는다** — 버튼을 누르는 대신 해석을
   다시 쓰는 학생이 많다. 스스로 고친 것이므로 `effect: "light"`. 그 외에는 D/E.
4. **좌절 임계인가?** (`missCountInUnit >= 3`)  
   정답 설명 + 쉬운 2지선다 하나 + 다음 unit. 결과 `설명제공`.
5. **진단** A / B / C / D / E.
6. **처치 하나**만 실행하고 학생을 기다린다. 혼자 다음 문장으로 가지 않는다.

## 5. 진단

| 코드 | 언제 | 누가 판정 | 처치 |
|------|------|-----------|------|
| **A** | 의미 보존 + `scoring_points` 반영. 어순·조사·직역/의역만 다르면 A | 데모: 키워드. 프로덕션: LLM 또는 키워드+LLM | 구체적 칭찬 → 다음 unit. 스스로 고친 턴만 `effect: "light"` |
| **B** | 포인트 일부만 맞음 | 프로덕션 LLM. 데모는 아직 거의 E로 접힘 | 맞은 점 먼저 인정, 틀린 점만 재시도 |
| **C** | `expected_errors` (데모의 P2, P3) | 코드 매칭. 고정 대사 | JSON 스크립트 그대로. 모델이 새로 설명 금지 |
| **D** | 해석 시도인데 A/B/C가 아님 | **프로덕션 LLM**. 데모는 E와 동일 | 위치만 짚기 → 되묻기 또는 2지선다 → 막히면 힌트 |
| **E** | 잘 모르겠어요 / 힌트 주세요 / 포기 / 무응답 | 코드 | 힌트 사다리 **한 단만** |

동시 오류면 `error_priority`의 **첫 번째 하나만**. 한 턴에 질문 둘 금지를 위해서다.

`never_mark_correct: true`인 오류(예: B.C.=기원후)는 절대 A가 아니다.

## 6. 엔진이 내는 액션

엔진이 먼저 액션을 고른다. LLM은 액션을 고르지 않고, 필요할 때만 **말을 만든다**.

| 액션 | 화면 | buttons | LLM? |
|------|------|---------|-------|
| `INTRO` | 교실 | 네, 좋아요! / 잘 모르겠어요 | 선택. 고정 인트로여도 됨 |
| `PRESENT_PROPER_NOUNS` | 교실 또는 학습 | — | 아니. 칩 + 한 줄 |
| `ASK_TRANSLATION` | 문장 학습 | 다 읽었어요 / 힌트 주세요 / 잘 모르겠어요 | 짧은 연결만 |
| `PRAISE_AND_ADVANCE` | 학습 → 다음 | — | 칭찬 문장만 다듬기 가능 |
| `TREAT_EXPECTED` | 학습, 말풍선 위 | JSON `choices` + 잘 모르겠어요 | **아니**. 고정 대사 |
| `TREAT_PARTIAL` | 학습 | 재시도 + 잘 모르겠어요 | 예 |
| `TREAT_UNEXPECTED` | 학습 | 되묻기/2지선다/힌트 | **예 (D)** |
| `HINT_1` / `HINT_2` / `HINT_3` | 학습 | 잘 모르겠어요 | 레슨 `hint_ladder` 우선. 없으면 모델이 단 구조만 지킴 |
| `FRUSTRATION_EXPLAIN` | 학습 | 쉬운 2지선다 | 톤만 모델, 정답은 데이터 |
| `DONE` | 교실 | 다시 시작 | `[기록]`은 UI에 안 보임 |

데모에서 C는 `TREAT_EXPECTED`, D는 `HINT_*`로 폴백.

## 7. LLM 계약 (붙일 때)

모델은 교습 순서를 발명하지 않는다. **이번 턴 액션의 대사**만 만든다.

### 입력 (system)

1. `frame.json` — 캐릭터, 절대 규칙, 힌트 사다리, 좌절 방지, 역질문
2. 현재 레슨 unit만 (전체 편지를 매 턴 넣지 말 것. 현재 문장 + scoring + expected_errors + hint_ladder + proper_nouns)
3. SessionState 요약 (`unitIndex`, `hintRung`, `missCount`, `pendingBranch`, `lastTutorUtterance`)
4. 이번 액션 열거

```text
action: TREAT_UNEXPECTED
unit: 3
do_not_reveal_answer: true
one_question_only: true
hint_rung_available: 1
max_sentences: 4
speech: 해요체
```

### 출력

앱 단계:

```json
{
  "message": "말풍선 2~4문장",
  "buttons": ["잘 모르겠어요"],
  "effect": null
}
```

- `buttons`가 비면 자유 입력만. `잘 모르겠어요`는 앱이 항상 넣을 수 있다.
- `effect: "light"`는 학생이 **스스로** 고친 A일 때만. 정답을 알려 준 뒤에는 null.
- `[기록]`은 세션 끝에 엔진이 만든다. 모델이 매 턴 출력하지 않는다.

### 가드레일 (코드가 거절)

- 모범 해석 문자열이 `HINT_3` / `FRUSTRATION` 전에 message에 있으면 드롭하고 힌트 1단으로 대체
- 문장 수 > 4
- 물음표가 두 개 이상 (한 턴 한 질문)
- `hintRung`을 건너뛴 내용
- 반말

## 8. 레슨 데이터

문장을 바꿀 때 고치는 유일한 곳. `content/tutor/lessons/*.json`.

한 레슨:

- `topic_intro`, `grammar_type`
- `proper_nouns[]` — `{ en, ko, type }` 해석 과제 아님. `ko`가 `en`과 같으면 그대로
- `proper_noun_tip` — 미리 한 번
- `chunks[]` 또는 `units[]` — 각 항목:
  - `text`, `model_translation`
  - `scoring_points`
  - `error_priority`
  - `expected_errors` (id, detect, signals, treatment.choices, on_choice)
  - `hint_ladder` 1·2·3
  - (선택) `p1` 키워드 그룹 — 데모 매칭용. 프로덕션은 LLM 판정으로 대체 가능

고정 대사가 있는 C는 모델이 문장을 바꾸지 않는다. 연결어만 최소.

## 9. UI 매핑

긴 채팅 로그를 쌓지 않는다. 선생님 **현재 한 줄**, 학생 **마지막 한 줄**.

| TutorView | 화면 |
|-----------|------|
| `screen: "chat"` | 교실. 인트로·종료. 말풍선은 캐릭터 **위** |
| `screen: "study"` | 문장 학습. 영어 문장 + 고유명사 하이라이트/칩 + 캐릭터 + 말풍선 **위** + 알약 버튼 + 입력 |
| `message` | 말풍선 |
| `buttons` | 핑크 테두리 알약. 타이핑 중 숨김 |
| `properNouns` | `Lewis Ltd. · 회사 이름 · 그대로` |
| `effect: "light"` | 스스로 교정한 순간만 |

설명 턴도 학습 화면에 머문다. 영어 문장을 보면서 되묻기 하기 위해서다.

## 10. 데모 vs 프로덕션

| | 지금 데모 | 프로덕션 |
|--|-----------|----------|
| A | 키워드 AND 그룹 | 키워드 보조 + LLM 의미 판정 |
| B | 거의 없음 (E로 폴백) | LLM |
| C | 키워드 → 고정 대사 | 동일. 코드 |
| D | E와 같음 | LLM, 위치→되묻기→힌트 |
| E | 힌트 사다리 | 동일. 코드 |
| 고유명사 | 인트로 한 줄 + 칩 | 동일. 코드 |
| 기록 | 종료 시 엔진. 네 값 모두 나옴 | 서버 저장, 말풍선 숨김 |

LLM을 붙여도 **C와 E와 카운터는 코드에 남긴다.** 여기까지 모델에 주면 선공개·힌트 점프가 다시 생긴다.

## 11. 하지 말 것

- 레슨 문장을 시스템 프롬프트에 하드코딩하고 다음 지문을 또 프롬프트에 넣기
- 매 턴 전체 대화 + 전체 레슨을 모델에 넣고 “알아서 수업해” 하기
- teach_points / 힌트 3단을 한 턴에 출력
- 고유명사를 해석 채점 포인트로 넣기
- haksup 튜터 로직 이식
- 말풍선 없는 메신저형 스크롤 채팅으로 바꾸기
