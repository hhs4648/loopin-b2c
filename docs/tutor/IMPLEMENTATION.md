# 구현 가이드 — 코드가 할 일 vs LLM이 할 일

다정쌤은 “똑똑한 챗봇”이 아니라 **고정된 교습 절차를 실행하는 튜터**입니다. LLM은 그 절차의 빈칸만 채웁니다.

## 1. 역할 분리

| 레이어 | 담당 | 예시 |
|--------|------|------|
| **프레임 (고정)** | 프롬프트 + `frame.json` + 앱 상태머신 | 단계 순서, 한 턴에 하나, 정답 선공개 금지, 힌트 3단, 좌절 방지 |
| **레슨 데이터 (교체)** | `lessons/*.json` | 문장, 청크, 모범 해석, expected_errors, 고정 대사, teach_points |
| **LLM 재량 (틀 안)** | 모델 | 예상 밖 오류 대응, 연결어, 부분 정답인지 판정, 같은 말 반복 피하기 |
| **앱 (나중)** | UI | 문장/청크 표시, `buttons` 렌더, `effect: "light"`, `[기록]` 파싱 |

구현할 때 LLM에게 교습 순서를 다시 발명하게 두지 마세요. 상태머신으로 단계를 지키고, 모델에게는 “지금 이 청크, 이 진단, 이 레슨 JSON”만 넘기는 쪽이 안전합니다.

초기에는 시스템 프롬프트 통째로도 테스트할 수 있습니다. 앱에 붙을수록 **상태 + 레슨 JSON은 코드가 들고, 모델은 한 턴 응답만 생성**하게 옮기세요.

## 2. 세션 상태 (코드가 반드시 기억)

한 수업 세션마다 상태를 유지합니다. LLM만 기억하게 두면 힌트 단수·좌절 카운트가 깨집니다.

**필드 목록은 [`ARCHITECTURE.md`](ARCHITECTURE.md) §3이 단일 소스입니다.** 이 문서에도
같은 표를 두었더니 두 벌이 서로 어긋났습니다(`chunkIndex` vs `unitIndex`,
`missCountInChunk` vs `missCountInUnit`). 실제 코드는 `src/tutor/engine.ts`의
`EngineState`입니다.

### 카운트 규칙

- `missCountInChunk`: 오답(A가 아닌 진단)과 “잘 모르겠어요/포기”를 **같은 청크 안에서 합산**.
- 힌트 사다리 1·2·3단을 쓰는 것도 miss에 포함됩니다 (“모르겠어요” 경로).
- 청크를 넘어가면 `hintRung = 0`, `missCountInChunk = 0`, `pendingBranch = null`.
- **4번째 miss부터** 시도를 강요하지 않고 좌절 방지로 전환. 결과는 `설명제공`. `skipFinalRetake = true`.

## 3. 한 턴 처리 순서 (앱이든 LLM-only든 동일)

학생 메시지가 오면 이 순서로만 판단합니다.

1. **역질문인가?** 해석 시도가 아니면 [학생 역질문] 처리 후 수업 복귀. 오답 카운트하지 않음.
2. **pendingBranch가 있는가?** 있으면 그 분기의 고정 대사만 실행 (E1 동사/과거분사 등).
3. **좌절 임계인가?** `missCountInChunk >= 3` 인데 또 실패/포기면 좌절 방지 처치. 힌트 사다리를 더 오르지 않음.
4. **청크 응답 진단** A / B / C / D / E.
5. **처치 1개만** 실행하고 학생 응답을 기다림.
6. 정답(A)이면 다음 청크 또는 마무리.

혼자 다음 단계로 넘어가는 응답은 버그입니다.

## 4. 진단 정의 (채점)

정답(A) 기준은 레슨 JSON의 `scoring_points`입니다.

- 의미가 보존되고 채점 포인트가 반영되면 **정답**.
- 어순·조사·직역/의역 차이만 있으면 정답으로 처리.
- 맞은 포인트 + 틀린 포인트가 섞이면 **부분 정답(B)**. 맞은 부분을 먼저 인정하고 틀린 것만 재시도.
- `expected_errors` 패턴과 맞으면 **C**. JSON의 고정 대사·분기를 그대로 따른다. 모델이 새로 설명하지 않는다.
- 그 외 오답은 **D**. 순서 고정: 위치만 짚기 → 되묻기 또는 2지선다 → 막히면 힌트.
- “잘 모르겠어요” / 무응답 / 포기는 **E**. 힌트 사다리를 **한 단만** 올린다. 건너뛰기 금지.

오류가 동시에 여러 개면 JSON의 `error_priority` 순서로 **하나만** 처치한다.
(이 문서의 `E1`~`E4`는 **탈레스 레슨**의 오류 id다. 퇴사 편지 레슨은 `P2`·`P3`를 쓴다 —
id는 레슨마다 자유이고, 코드는 `error_priority` 순서만 본다.)

## 5. 고정 대사가 있는 분기

expected_error에 `script`가 있으면 LLM이 문장을 바꿔 쓰지 않습니다. 의미만 같고 표현이 다른 말은 “같은 말을 반복하지 않는다” 규칙과 충돌하므로, **고정 대사는 그대로**, 연결어만 최소로 붙입니다.

학생이 고정 질문(“Born이 동사일까요, 과거분사일까요?”)에 예상 밖 답을 하면 D 처치로 떨어지되, 그 질문의 정답(과거분사)을 먼저 공개하지 않습니다.

## 6. 마무리와 기록

- 세션 중 오류가 하나라도 있었고 `skipFinalRetake === false` → “오늘 배운 걸 모아서, 한번 전체적으로 해석해볼까요?”
- 오류가 없었으면 칭찬 후 종료.
- 좌절 방지가 발동했으면 전체 통합 재시도 **생략**.
- 마지막에 학생에게 보이지 않는 한 줄:

```
[기록] 유형=<grammar_type> / 결과=이해|오류후이해|설명제공|취약 / 오류=<발생한 오류 id들>
```

결과 값:

| 값 | 언제 |
|----|------|
| `이해` | 오류 없이 통과 |
| `오류후이해` | 오류가 있었으나 학생이 스스로 (또는 힌트 후) 교정 |
| `설명제공` | 좌절 방지로 정답을 설명해 줌 |
| `취약` | 힌트 3단(모범 해석 공개)을 봐야 넘어간 문장이 하나라도 있는 경우 |

앱 단계에서는 `[기록]`을 파싱해 저장하고 말풍선에서는 숨깁니다.

**판정 순서는 강한 신호부터입니다** (`engine.ts`의 `advance`):
`설명제공`(좌절 방지 발동) → `취약`(힌트 3단 도달) → `오류후이해`(오류는 있었으나 스스로 교정)
→ `이해`. 3단이 없는 레슨에서는 `취약`을 세지 않습니다 — 학생이 정답을 본 적이 없는데
「취약」으로 남으면 기록이 거짓말이 됩니다.

힌트 3단으로 넘어간 문장은 `오류=3:HINT3`처럼 같이 남깁니다. 예상 오류만 기록하면
「결과=취약 / 오류=없음」이 나옵니다.

## 7. UI 셸 + JSON (나중 단계)

앱 화면은 상냥쌤 프로토타입과 같은 형식이다. 자세한 레이아웃은 `docs/tutor/UI.md`, 토큰은 `content/tutor/ui-shell.json`.

- 화면 1 교실 대화: 캐릭터 + 흰 말풍선 + 빠른 대답 알약 + 둥근 입력바
- 화면 2 문장 학습: 큰 영어 문장 + 작은 선생님 말풍선 + `해석을 적어 보세요…`
- 긴 대화 로그를 쌓지 않는다

앱에 붙을 때 시스템 프롬프트 절대 규칙 아래에 추가합니다. **지금은 프롬프트 테스트 단계이므로 기본 시스템 프롬프트에 JSON 강제 출력을 넣지 마세요.** 넣으면 대화 테스트가 깨집니다.

```json
{
  "message": "말풍선 내용",
  "buttons": ["잘 모르겠어요"],
  "effect": null
}
```

- `buttons`: 2지선다, “그렇군요~”, “더 알고 싶어요” 등. 자유 입력만이면 `[]`.
- `effect`: 학생이 **오류를 스스로 교정해낸 순간만** `"light"`. 정답을 알려준 뒤에는 켜지 않음.

레슨 JSON의 선택지(`choices`)가 곧 `buttons` 후보입니다.

## 8. 구현할 때 하지 말 것

- 레슨 문장을 시스템 프롬프트에 하드코딩한 채 두 번째 문장을 추가하기 (JSON으로 분리).
- teach_points를 한 턴에 전부 출력하기.
- B.C. = 기원후를 사소한 실수로 통과시키기 (E4, `never_mark_correct: true`).
- 고유명사 팁을 청크마다 반복하기.
- haksup 앱의 튜터/채점 로직을 그대로 가져오기.
