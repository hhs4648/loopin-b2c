# 어법 유형 틀 (v1 — 2026-10-20)

기준 레슨: **2022년 3월 29번**(`gen_moeui_2022_03_29.py`, 「밑줄 친 부분 중 어법상 틀린 것」, 오답률 1위).
공통 틀은 [README](README.md). `method.type = "grammar"`, 풀이법 이름 `["밑줄 문법 확인", "틀린 것 고르기"]`.

## 푸는 법 (선생님)

1. 어법 문제는 다른 문제들과 달리 **문법만 보면 된다** — 해석·요지보다 밑줄의 문법 규칙
2. 밑줄마다 **이 밑줄이 무엇을 묻는지**(동사냐 분사냐 / 짝이 맞나 / 형용사냐 부사냐 / 도치 …)를 먼저 정한다
3. 그 규칙을 배우고 → 이 밑줄이 규칙에 맞는지 **학생이 직접 판단**한다
4. 맞는 밑줄을 다 걸러 내면 남은 하나가 답

> **주어·동사 찾기를 하지 않는다** (2026-10-20 선생님) — 어법 문제는 밑줄 문법 위주로 자세히. 대신 주어·동사가 설명에 필요한 화면은
> 끊어읽기를 저절로 켜서 S·V를 보여 준다(`slash_on`, 말에 「주어」·「목적어」가 있으면 자동).

## 화면 순서 (밑줄 하나마다)

정답이 **아닌** 밑줄(29번 ①③④⑤)은 아래를 다 한다. 정답 밑줄(②)은 구조만 짚고 맞다/틀리다는 문제에서 고른다.

| # | 화면 | 만드는 법 | 29번 ③ consisting 예 |
|---|---|---|---|
| 0 | 도입 | 주제 한 줄 + 칠판 그림(매번), 풀이법 「어법 문제는 다른 문제들과 달리 문법만 보면 돼요. 그래서 이번 유형은 문법 설명 위주로 갈게요.」(처음만) | |
| 1 | **이 밑줄이 묻는 것** | `show` — 「보기 ③consisting부터 볼게요. 이번 밑줄은 '동사'가 와야 하는지 '분사'가 와야 하는지 고르는 문제예요.」 | |
| 2 | **규칙 표** + 보충학습실 | `show` + `panel=rows(...)` 표, **표 아래 버튼** [나중에 보충학습실에서 더 깊이 공부할게요](`practice`·`practice_button`, brief `saved`) | 동사(~하다: learn · learned/wrote · will learn · is learning) / 분사(~하는·~된: learning · learned/written) |
| 3 | **외울 것 / 헷갈리는 이유** | `show` 한 화면 + 칠판 한 줄. 「꼭 외워 둘 것」은 규칙일 때만 — 지문 특성 때문에 헷갈리면 이유로 말한다(④: 「목적어가 길어서 헷갈려요. 중간에 in which 절이 들어왔기 때문」) | 한 문장에 동사는 하나 — and·or·when 같은 접속사가 있어야만 동사 추가 |
| 4 | **맞을까요, 틀릴까요?** | `judge(...)` — 「그럼 보기 ③은 어법상 맞을까요, 틀릴까요?」 [맞는 표현]/[틀린 표현]. 맞히면 칭찬만 한 화면(`praise_alone`), 밑줄 점검표가 칠판에 남는다(`panel_after`) | |
| 5 | **해설** | `show` + 칠판(구조 표). 주어·동사가 나오면 끊어읽기 저절로 | 이미 It seems, Greek music was라는 주어·동사가 있고 접속사가 없어요 → 동사 못 옴 → 분사 |
| 6 | **문법 이름** (있으면) | `show` + **공식 한 줄 칠판**(`panel.kind = "formula"`: 조각마다 밑줄·아래 이름) | S + V … , ‾‾-ing 또는 p.p. …‾‾(분사구문) + 지문 예 |
| 7 | **[심화]** (선택) | `detail_button` + 그 뒤 스텝에 `optional_of` — 누른 학생만. 보기에 없는 말(consisted, being …)은 **여기서만** 꺼낸다 | consisted는 동사로도 p.p.로도 안 된다 |
| 8 | 더 연습할까요? | `practice_offer(id, drill)` [네]/[괜찮아요] — 2번에서 이미 담았으면 저절로 건너뜀 | |

nor처럼 **규칙이 여러 단계**인 밑줄(①)은 3번 대신 칠판에 한 줄씩 쌓는 설명 화면 여러 개(`nor_board`) → **바로 연습**(두 문장 합치기 객관식, 보기마다 틀린 이유 다르게) → 4번으로.

**정답 밑줄**(②): 그 문장에서 구조만(「more는 두 가지를 비교하는 말이에요. more와 짝을 이루는 말이 무엇인지 떠올려 봐요.」), 판단은 문제에서.
드문 유형이면 **정답을 맞힌 뒤** 참고 한 화면(`exam.brief.answer_note`): 「more·as 짝은 모의고사에 거의 안 나와서 오답률 1위였어요. 보통은 동사냐 분사냐 같은 것을 물어봐요.」

## 보충학습실 drill (문법마다)

- 자료 `content/tutor/grammar-drills/<id>.json` — 10문제, 처음 객관식 → 뒤로 갈수록 주관식 섞기, 시작 전 **규칙 카드**(`intro`: 언제 → 어떻게)
- 큰 문법은 **묶음**(`categories/<id>.json`)으로 세트를 늘린다 — 「nor / so」 = 기본 개념 · nor vs so · nor vs neither · 작문(한국어 보고 뒷부분 쓰기). 좋은 문제는 빼지 말고 세트를 늘린다(틀릴 만한 경우를 하나씩 다 다루기)
- 주관식은 규칙 채점(줄임말·대소문자 무시, 맞는 모양 여러 개), 학생 답은 그대로 기록

## 만들 때 체크리스트

- [ ] 주어·동사 찾기(`sv`) 스텝이 없다. 관계사절 안 S·V는 `roles`에 안 넣고 `modifiers`로 [ ]
- [ ] 밑줄마다 1번 「이 밑줄이 묻는 것」을 **보기에 있는 말로만** 말했다(보기에 없는 형태는 심화에서만)
- [ ] 규칙 표는 해설지 번역과 맞춰 봤다. 뜻(「consist of = ~로 구성되다」)·예문이 정확하다
- [ ] 4번 「맞을까요, 틀릴까요?」가 **「더 연습할까요?」보다 앞**에 있다. 「①has는 맞아요」라고 먼저 알려 주지 않는다
- [ ] 「밑줄 점검표에 붙여 둘게요」 같은 화면 중계 말이 없다
- [ ] 문법마다 drill 자료가 있고, `practice`·`practice_offer`가 그 id(또는 묶음 id)를 가리킨다
- [ ] 정답 밑줄 해설에 정답을 미리 말하지 않는다. 드문 유형이면 `answer_note`
- [ ] 쉬운 말: 「견주다」 ✕ → 「비교하다」, 「빈자리」 같은 수업 안 말 ✕
- [ ] `npm run policy:copy stamp <id>` → `npm run build`

## 정한 것

- 어법은 S·V 찾기 없이 밑줄 문법 위주 (2026-10-20 선생님)
- 맞는 밑줄은 알려 주지 말고 학생이 「맞을까요, 틀릴까요?」로 판단 (2026-10-20)
- 보기에 없는 말을 먼저 꺼내지 않는다 — 「consisted가 왜 갑자기?」(2026-10-20)
- 규칙 표 아래에 보충학습실 버튼, 담은 문법은 뒤 「더 연습할까요?」 건너뜀 (2026-10-20)
- 「목적격 보어」「분사구문」처럼 문법 이름은 공식 칠판과 함께 — 배경 설명 없이 이름만 칠판에 쓰지 않는다 (2026-10-20)
