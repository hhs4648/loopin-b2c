# 순서 유형 틀 (v1 — 2026-10-15)

예시 레슨: 3월 36번(`gen_moeui_2026_03_36.py`) · 6월 37번(`gen_mopyeong_2026_06_37.py`). 공통 틀은 [README](README.md).
공용 도구: `scripts/lessons/order_tools.py` (`card`, `order_link`).

## 푸는 법 (선생님)

1. 주어진 글이 **무엇으로 끝나는지** 본다 — 다음 내용은 **그 글의 논리**로 예측한다. 「긍정으로 끝나면 다음은 반전」 같은 일반화는 쓰지 않는다 (2026-10-15 선생님: 긍정문으로 끝난다고 다음이 부정이 되는 건 아니다)
2. 단락마다 **첫머리**가 앞의 무엇을 받는지 본다 — This·the·such·in this manner(가리키는 말), Nor·However·The problem(연결·반전)
3. 단락의 **끝**이 다음에 무엇을 부르는지 본다 — not all(→ 그 조건), 쓸모 있는 말(→ 그 예) …
4. 앞 단락의 끝 ↔ 다음 단락의 첫머리가 이어지게 놓는다

## 만들 때 체크리스트

- [ ] 문장을 시험지 순서 (A)→(B)→(C)로 넣었다. `paper_order`는 주어진 글의 마지막 화면
- [ ] 단락마다 첫 문장 `_before`, 끝 문장 `_next`(다음을 부르는 말이 있을 때만). 가운데 문장은 한 줄
- [ ] **순서를 고르기 전에 어느 단락이 앞·뒤인지 말하지 않는다** — 「앞에서 읽은 (A)가 그 조건」 같은 말 금지 (37 c2_next에서 고침, 2026-10-15)
- [ ] `order_link` 카드의 첫머리·끝은 단서가 보이게 짧게(…로 줄임), 한국어 뜻을 단다
- [ ] 많이 고른 오답(오답률 표)을 보기 설명에 반영했다
- [ ] `npm run policy:copy stamp <id>` → `npm run build`

## 정한 것

- **「문장 1·2·3」이라는 말 자체를 쓰지 않는다**(태그·위쪽 진행 표시·헷갈린 포인트 모두 주어진 글 / (A) …) — 문장 순서가 의미 없다.
- 화면에는 「문장 3」이 아니라 **(A)·(B)·(C)** 로, 단락이 여러 문장이면 태그 옆 **‹ ›** 로 단락 안의 다른 문장을 오가며 본다(점 = 단락 안 자리). 연하게 함께 띄우는 방식은 별로라 뺐다 (2026-10-15 선생님).
  선생님 말도 「(A) 단락」, 「(A) 단락의 두 번째 문장」 (2026-10-15 선생님, 순서 문제 공통 규칙). `method.type = "order"`면 저절로 된다

- 읽는 순서는 **시험지 순서** — 정답 순서로 읽으면 답을 미리 안다. 대신 (A) 앞에서 한 번 알린다 (2026-10-14 선생님)
- 단락 안은 **첫·끝 문장만 자세히**, 가운데는 읽기 + 한 줄 (2026-10-15 선생님)
- 마무리는 **학생이 직접 잇기** — 단서 표를 보여 주는 대신 카드를 끌어 놓는다 (2026-10-15 선생님)

## 시범 중
