## 푸는 법 (선생님)

1. **주어진 문장의 단서 찾기** — 지시어(This·such·These), 연결어(Nonetheless·But·Instead), 대조(stands in contrast to·as opposed to), 관계사(which)
2. **앞에 올 내용 예측하기** — 단서가 가리키는 대상이나 반대 상황. **근거가 있을 때만** 묻는다
3. **흐름이 끊기는 곳 찾기** — 지문을 처음부터 읽으며 ①~⑤ 자리마다 앞뒤가 그대로 이어지는지

**주어진 문장 정석 순서** (2026-10-18 선생님, 2024년 3월 39번):
This가 무엇과 대조되는지 → which가 가리키는 것 → 그 대상의 특징 → 그러니 This(앞)에는 그 반대가 온다. 개념 차이는 **칠판 그림**으로 먼저.

## 만들 때 체크리스트

- [ ] 주어진 문장 `id: 1`, `label: "주어진 문장"`, `exam.sentence = 1`. 지문 문장엔 `(①)`처럼 자리 번호
- [ ] 단서(지시어·연결어·대조·관계사)를 골랐다. **「앞에?」는 근거가 있을 때만, 「뒤에?」는 묻지 않는다** (2026-10-18 — 정답을 알고 거꾸로 맞춘 억지)
- [ ] ①~⑤ 모든 자리에 흐름 확인, 끊김은 정답 자리 하나
- [ ] 개념 대비가 있으면 그림 칠판, 칩이 그림 글자와 안 겹친다
- [ ] `passage_keywords`는 단어만·최소 — 선생님이 뺀 말(admittance processes, tests …) 넣지 않기
- [ ] 보기 `ko`는 「… 뒤」로. 많이 고른 오답은 `option_feedback`(한두 줄 — 제출 뒤 보기 아래 요약으로 뜬다)·`review`
- [ ] *로 풀어 준 단어는 핵심어에서 빼고, 해설지와 대조했다
- [ ] 주어·동사 찾기 스텝을 새로 만들지 않는다(엔진이 건너뜀 — 끊어읽기가 대신)
- [ ] `npm run policy:copy stamp <id>` → `npm run build`
