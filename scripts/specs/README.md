# 지문 고치기

**레슨 JSON(`content/tutor/lessons/*.json`)을 고치지 마세요.** 그건 생성물이라
다음 빌드에서 통째로 덮어써집니다. 고칠 곳은 언제나 이 폴더의 스펙입니다.

```
scripts/specs/suneung-21.json     ← 여기를 고치고
npm run lessons                   ← 다시 뽑고
npm test                          ← 확인
```

한 지문만 다시 뽑으려면 `npm run lessons scripts/specs/suneung-21.json`.

## 무엇이 이상하냐에 따라 고칠 자리

| 학생이 겪는 일 | 고칠 곳 | 예 |
|---|---|---|
| 해석이 어색하다 | `chunks[].ko` | 통과할 때 학생에게 보여 주는 문장 |
| 맞게 썼는데 못 알아본다 | `chunks[].points[].check` | 학생이 쓸 법한 표현을 더 넣는다 |
| 엉뚱한 답도 맞다고 한다 | `chunks[].points[].check` | 너무 넓은 키워드를 뺀다 (`"일"` 같은 것) |
| 유도가 가리키는 자리가 틀렸다 | `chunks[].points[].en` | 유도·알려주기 문구가 여기서 만들어진다 |
| 답 알려주기가 어색하다 | `chunks[].points[].answer` | `tell`이 여기서 만들어진다 |
| 이 오해는 실제로 안 나온다 | `chunks[].errors` | 통째로 지운다 |
| 자주 걸리는 오해가 빠졌다 | `chunks[].errors` | 아래 모양대로 하나 추가한다 |
| 2지선다 보기가 이상하다 | `chunks[].errors[].wrong` / `.right` | 좌절 방지에서 쓰는 보기 짝이다 |
| 문장이 너무 길다/짧다 | `chunks` | 나누거나 합친다. `text`·`ko`·`points`를 같이 옮긴다 |
| 단어를 눌러도 뜻이 이상하다 | `chunks[].glosses` | 여기 적은 것이 공용 사전을 이긴다 |
| 카드 제목·부제 | `content/tutor/sets.json` | 스펙이 아니라 목록 파일이다 |

## 채점 포인트 하나의 모양

```json
{
  "en": "serve",              // 유도가 집는 이름. 물음표를 넣지 마세요
  "sub": "가",                 // en 뒤에 붙는 조사 (이/가)
  "top": "는",                 // 알려줄 때 붙는 조사 (은/는)
  "answer": "근무하다",         // 정답. tell에 그대로 들어간다
  "check": ["근무", "일하", "일했"]   // 이 중 하나라도 있으면 맞은 것으로 본다
}
```

여기서 자동으로 만들어지는 것:

```
nudge : serve가 아직 해석에 안 나왔어요. 한번 더 해볼까요?
tell  : serve는 여기서 '근무하다'예요.
```

**`points`의 순서가 곧 수업 순서**입니다. 엔진이 못 낸 것 중 첫 번째부터 짚습니다.
쉬운 것을 앞에 두세요. 한 문장에 2~3개가 적당합니다.

## 오해 하나의 모양

```json
{
  "id": "E1",
  "detect": "serve를 '봉사하다'로 해석",        // 사람이 읽는 메모
  "signals": ["봉사", "섬기"],                 // 학생 답에 이게 있으면 이 오해로 본다
  "ask": "여기 served는 물건이 하는 일이에요.",   // 2지선다 앞에 붙는 한마디
  "wrong": "봉사했다",
  "right": "~ 역할을 했다"
}
```

`wrong`/`right`는 **짝이 맞아야** 합니다 — 좌절 방지에서 이 둘을 보기로 냅니다.
한쪽이 문장이고 한쪽이 낱말이면 문제가 아니라 받아쓰기가 됩니다.

`signals`는 좁게 쓰세요. `"일"`처럼 흔한 글자를 넣으면 멀쩡한 답이 오해로 잡힙니다.

## 빌드가 잡아 주는 것

`npm run lessons`가 그 자리에서 알려 줍니다.

```
! 문장3 뜻 없음: require              → 그 낱말을 누르면 빈칸이 나온다
  (구가 문장에 없어 안 잡힘: "rely on")  → 문장은 "rely exclusively on"이라 안 걸린다
항목 이름에 물음표를 넣지 마세요       → 유도 문구에 질문이 둘이 된다 (빌드 중단)
```

`npm test`가 잡아 주는 것: 유도가 정답을 흘리는지, 뜻을 알려 주고 번역어만 묻는지,
안 한 오해를 미리 부정하는지, 목록에 없는 지문이 남았는지.

## 되풀이되는 낱말

`content/tutor/glossary.json`에 넣으면 모든 지문이 씁니다. 그 지문에서만 다른
뜻이면 스펙의 `glosses`에 적으세요 — 그쪽이 이깁니다.
